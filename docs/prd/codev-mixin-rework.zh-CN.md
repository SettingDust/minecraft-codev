# Codev Mixin 重整

> 本文是[英文原稿](./codev-mixin-rework.md)的中文译本，描述同一产品目标，不是第二份独立权威。

**状态：生效（Active）。**

## 问题、使用者与预期结果

使用者（调用本构建能力的一方）需要一份由真实 Mixin 引擎按指定 Mixin 处理的 Minecraft 构建副本。Codev 提供并执行真实预应用和精确的配置条目清理。在调用方注册和组合的完整清理流中，所消费的目标须是真实引擎处理后的可用输出，处理后的配置须不再包含逻辑身份已收到引擎应用通知的条目。Codev 不额外证明应用无报错或完整完成。完成的组件产物可按该组件实际产出的成果消费；仅有已应用的目标不代表清理完成。不同处理必须互不影响；日志和异常让处理过程与失败可观察。

Codev 不限制谁消费输出，也不限制输出用于编译、反编译、打包还是运行。使用者自行决定用途和接入方式；这些举例不是支持矩阵，也不保证所有下游用途都兼容或安全。

## 产品需求：按构建顺序说明

### 1. 使用者提供什么

**R3 — 用对输入。** 使用者指定待处理的目标 JAR、承载 Mixin 配置和类的来源、解析它们所需的依赖、任务插件及资源，以及预期环境（如客户端/服务端），并按 R8 提供必要的命名映射和 refmap 上下文。通用引擎选项沿用 Mixin 原生的宿主系统属性及默认行为；Codev 不重新解释这些选项，也不提供逐任务独立覆写通用选项的能力。Codev 必须一致地使用这些输入，不能让宿主或 Loader 的依赖悄悄替换预期执行组件。必需的引擎输入解析有歧义或输入不可用时，应明确失败，而不是猜一个继续处理；plugin/refmap 的可用性按 R6 处理，不放宽 R8。输入产物间出现重复的清理身份，本身不构成无效输入。

**R8 — 名称对应正确。** 当输入对同一个类或成员使用不同名称时，使用者提供必要的命名映射、明确的来源 → 目标方向，以及需要时的 refmap 上下文。refmap 是帮助解析 Mixin 所引用名称的资源。Codev 必须找到预期的类、方法或字段，不能混淆所属类、重载或描述符。名称已经一致的输入不必强制提供映射。映射无效、显式指定的上下文不可用或必需的名称解析失败时，应明确失败，不能随意匹配。

### 2. Codev 如何处理

**R2 — 每次处理互不串扰。** 每次操作都在构建副本上工作，使用自己的执行状态。无论成功、失败还是取消，都不能让 Codev 所负责的配置、插件或映射状态残留并影响另一操作。独立操作并发执行应与串行结果一致，输出位置冲突时不能混合结果。Codev 必须释放自己持有的资源，重试不受上次状态影响；这不承诺为任意插件的外部影响提供沙箱。

**R4 — 真正应用。** Codev 用真实的 Mixin 引擎修改指定目标，并记录引擎提供的应用通知。仅发现配置或找到候选项不能使条目取得清理资格；收到引擎应用通知即可。Codev 不自行验证注入语义、处理无报错或所有目标均完成，不解析引擎日志裁定成功，也不重建引擎自身的验证义务。引擎输出日志，由使用者自行阅读。Codev 完成输出生产不表示所有请求的应用都成功。

### 3. Codev 交付什么，清理什么

**R5 — 交付已应用的目标和已清理的依赖副本。** 调用方注册、组合并请求完整清理流时，Codev 必须执行真实预应用和精确的配置清理。所消费的目标须包含真实 Mixin 引擎的处理输出，处理后的配置须不再包含逻辑身份已收到引擎应用通知的条目。调用方必须为所有要求处理的副本选用并消费对应的清理结果，包括含有配置的派生目标，不能把已应用的目标当作已清理。Codev 实现清理算法；调用方配置和连接这些能力，而非自行实现替代清理。清理的逻辑身份由完整配置资源路径和 Mixin 数组中的原始条目字符串组成，取包名展开或名称映射之前的字符串。收到引擎应用通知，该身份即进入移除集合，无需另行证明处理无报错或所有目标、物理来源均完整应用。部分应用、日志报错或其它位置完成状态未知，不取消已收到通知的身份的清理资格；异常及输出生产失败仍按 R6 传播。

对于移除集合中的每个身份，Codev 从所有处理后的依赖副本的 Mixin 数组中移除全部匹配的物理出现位置，包括重复条目、不同数组及不同 JAR 中的匹配。清理匹配不使用来源标识、来源路径、哈希或逐来源唯一性检查。这也会移除另一物理来源中的同键条目，无需单独确认该处条目已完成应用。身份未进入移除集合的条目保留；仅类名相同，不能匹配配置资源路径或原始条目字符串不同的条目。其余字段及值（包括未知字段）、保留条目的顺序和无关资源必须保持不变。Mixin 类、refmap、配置文件和 Loader 元数据保持完整。

### 4. 输出交给谁

Codev 提供可供使用者或集成插件注册和组合的预应用、配置清理能力。Codev 实现并执行这两项能力；使用者或集成插件负责注册和配置、连接输入输出，并选择哪些依赖配置消费转换结果。这不要求使用者自行实现清理，也不要求 Codev 自动注册能力、选择消费配置或提供统一交付路由。

**R10 — 用途自主，输出完成。** 使用者决定谁消费完成的转换目标和处理后的依赖副本，以及用于什么目的。Codev 不得施加仅编译/反编译的用途限制、禁止打包或运行，或要求按用途隔离消费方路由。这不保证所有下游用途都兼容或安全，也不要求 Codev 选择或实现这些路由。

原始目标和承载 Mixin 的来源产物保持不变；依赖配置清理只发生在独立副本中。无论后续用途如何，Codev 仍负责各组件自身的完整产出和精确清理。完成的组件产物可按其实际成果消费；调用方须组合并消费所有要求的清理结果，才能获得完整清理流。引擎或生产方正常返回，本身不代表组件发布成功或所请求的清理流完成。

所有会影响输出的输入都要纳入构建输入/输出跟踪，包括配置、类、插件及资源、依赖、环境和选项，以及用到的映射。输入变化后应得到对应当前输入的结果。正常从缓存恢复的组件结果必须对应当前输入，仍可使用，不依赖生产操作的内存状态。仅恢复已应用的目标不代表清理完成：调用方所请求的完整清理流须执行或正确复用所有要求的清理结果，并保留其生产依赖。当前构建失败时，不能拿陈旧结果顶替成功。

### 5. 失败如何处理

**R6 — 诊断真实，产物安全。** 引擎抛出的异常、无效输入、取消，以及导致 Codev 无法完成自身输出生产的转换、依赖清理或输出写入失败，都应通过向外抛出异常停止受影响的生产，阻止其半成品或陈旧结果作为当前成功结果被消费。不得吞掉引擎异常。要求的清理失败必须传播到受影响的消费，不能报告所请求的清理流成功；这不否定独立完成的已应用目标，也不要求跨任意调用方任务的事务。不得覆盖原输入；无效归档路径不能导致向预期输出之外写入。

引擎只记报错日志或仅部分应用 Mixin，但正常返回时，这本身既不使 Codev 的输出生产失败，也不取消已收到通知的清理身份的资格。plugin/refmap 的可用性遵循引擎原生 required/optional 及 fallback 行为：引擎对不可用的 plugin 或 refmap 正常返回（包括返回默认 mapper）时，Codev 不得自行将该结果升级为失败。这不豁免 R8 对命名映射及显式请求的 refmap 上下文的要求。引擎日志由使用者自行阅读，Codev 不解读日志裁定应用成功。完成输出不能被当作所有请求的应用都成功的证明。Codev 自身的失败须通过日志或异常可见，说明失败阶段、已知的相关配置或目标，以及底层原因；无法归因时要明确不确定，不能编造身份。

### 简短期望流程

使用者提供 Minecraft JAR、某个依赖 mod 的 Mixin 输入、解析依赖和必要的命名映射，并为完整清理流注册和组合能力 → Codev 在独立构建副本上调用真实 Mixin 引擎，收到引擎应用通知即将清理身份纳入移除集合 → 调用方将产出的清理信息连接到 Codev 的清理能力，并选择消费的依赖配置 → Codev 从要求处理的副本（包括含有配置的派生目标）移除这些配置路径/原始条目字符串组合的全部出现位置，保留身份未进入集合的条目 → 调用方消费对应的完成目标和已清理依赖结果，自行决定用途，无需自行实现 strip 算法。使用者自行阅读引擎的处理及失败日志。清理依据应用通知，不依赖额外的完整应用或无报错证明，也不依赖使用者预期的下游用途。异常或导致 Codev 无法完成自身输出生产的失败应停止受影响的构建，而不是提供半成品；引擎部分应用或仅记报错日志但正常返回，本身不构成此类失败。

## 范围限制

本能力涵盖真实 Mixin 预应用、精确的依赖配置条目清理、完成产物交付和诊断可见性。下游接入、防止运行时重复应用以及打包/分发保证不在范围内。日志和异常提供诊断；不要求结构化诊断返回、独立 records 或消费方复演。

无关构建系统重设计、自动升级引擎、新增扩展或 Loader 支持承诺，以及完整兼容矩阵不在范围内。具体 API、任务结构、内部通信、输出布局和缓存机制属于技术选择，而不是产品需求。

## 可观察验收

验收采用小型真实引擎 class/JAR 样例和针对使用者构建流的定点检查；不以下载或启动游戏为前提。

- **AC3 — 使用指定输入（R3）。** 操作使用指定的配置、类、依赖、环境和任务插件资源，不被宿主悄悄替换。必需的引擎输入解析有歧义或输入不可用时明确失败，但遵循 R6 的引擎原生 plugin/refmap 政策且不放宽 R8；仅清理身份重复不导致验证失败。修改影响输出的输入后，得到对应当前输入的结果，而不是复用陈旧输出。
- **AC9 — 名称正确（R8）。** 需要映射的真实应用到达预期成员，包括所属类不同的同名成员或重载。名称已经一致的应用无需映射也能工作。映射无效、指定上下文不可用或必需的名称解析失败时，不能提供虚假的成功输出。
- **AC2 — 状态不串扰（R2）。** 一次操作使用配置、插件或映射状态后，另一输入不同的操作不受其影响，失败后重试也如此。独立并发结果与串行一致；冲突的输出位置不合并结果，持有的资源得到释放。
- **AC4 — 结果和失败真实（R4、R6）。** 完成的输出中能观察到真实成功的注入。仅有发现或候选回调不能使清理身份取得资格。引擎部分应用或只记报错日志但正常返回时，其日志仍供使用者自行阅读；Codev 不自行验证注入语义、不解析日志裁定成功，也不要求完整应用或无报错证明。输出完成不被报告为所有应用均成功的证明。引擎按原生 required/optional 或 fallback 行为正常处理不可用的 plugin/refmap（包括返回默认 mapper）时，不得升级为 Codev 失败；R8 的映射/上下文要求保持不变。引擎异常、该引擎原生政策之外的无效输入、取消或导致 Codev 无法产出输出的失败，要向外抛出异常，阻止当前半成品或陈旧结果被消费，并提供阶段和底层原因；相关身份已知时一并说明。
- **AC5 — 精确清理依赖（R5、R4、R6）。** 在调用方注册和组合的完整清理流中，调用方消费所有要求处理的副本的对应清理结果，包括含有配置的派生目标。所消费的目标包含真实引擎的处理输出，对应的处理后配置不再包含逻辑身份已收到引擎应用通知的条目。Codev 执行清理算法；仅有已应用的目标或可移除条目名单，不满足这一完整流验收条件。覆盖一个条目涉及多个目标的情况：逻辑身份一旦收到应用通知，即移除全部匹配项，即使另一目标或物理出现位置失败、未完成或完成状态未知，而引擎正常返回。身份取得资格不需要额外的无报错或完整应用证明；引擎异常及 Codev 输出生产失败仍停止受影响的生产。按完整配置资源路径和 Mixin 数组中的原始条目字符串匹配：不使用来源标识、来源路径、哈希或逐来源唯一性检查，一并移除不同数组及 JAR 中的全部匹配位置，即使另一来源中的条目没有单独的完成确认。配置路径或原始条目字符串不同就不匹配；身份未进入集合的条目保留。清理保留其余字段及值（包括未知字段）、保留条目的顺序和无关资源，原始产物不变。日志或异常使失败可观察。
- **AC11 — 用途自主和缓存安全（R10）。** Codev 不限制消费方身份或输出用途，不要求按用途隔离路由；下游路由由使用者决定，不表示任意下游用途都兼容或安全。原输入保持不变。各组件自身的生产和发布成功之前，不能仅凭引擎或生产方正常返回就认定该组件完成。正常完成的预应用目标可作为已应用目标消费，但不能冒充已清理目标或所请求的清理流完成。要求的清理失败传播到受影响的消费，不否定另一独立完成的组件。正常从缓存恢复的组件输出无需生产方内存即可使用，并与当前输入对应。请求完整清理流时，调用方消费所有对应的清理结果，包括含有配置的派生目标；正常执行或有效缓存复用后，要求的条目清理仍须完整成立。

## 依赖与风险

[操作隔离 ADR](../adr/mixin-operation-isolation.md) 定义 Accepted 的操作级架构；[Spec](../spec/mixin-preapplication.zh-CN.md) 定义本产品目标的技术处理和交付合同。

使用者已接受[三图设计](../design/mixin-design.html)，原中英文 Spec 已按该已接受结构完成规范同步。选定的调用结构、输入/输出表示、应用通知接点、内部通信及生产者完成边界见 [Spec](../spec/mixin-preapplication.zh-CN.md)；其余实现细节是在该合同内的选择，而非设计整体未定。Codev 负责实现预应用和清理，使用者或集成插件负责注册、组合和消费选择，以及通知即清理资格和全匹配移除，均保持不变。本轮重实现、验证与验收尚未开始；历史实现与验证仍是历史事实，不作为已接受新设计已实现或已验收的证据。

主要风险是将输出用途不受限制误解为保证下游兼容或安全，或将应用通知当作完整应用、无报错的证明。按通知批量匹配会有意移除不同物理来源和目标涉及的同键条目，即使部分应用尚未完成或未获确认；没有收到通知的身份的条目保留。使用者须自行阅读引擎日志判断应用问题。准确记录通知、清楚的诊断和安全的完成产物仍是关键。
