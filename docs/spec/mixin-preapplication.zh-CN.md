# Mixin 预应用

> 本文是[英文原稿](./mixin-preapplication.md)的中文译本，描述同一技术合同，不是第二份独立权威。

**状态：与目标对齐的技术合同——三图设计、重复对象键策略、字符串内未转义控制字符策略、后续八点简化、默认 UTF-8 解码及 JDK 资源打开失败语义已接受；尚未确立新设计的实现、验证与验收。** 技术所有者：`minecraft-codev-mixins`，下游输出用途与接入由使用者决定。这些是系统边界，不是新指定的维护者。下文的**必须**、**不得**和**可以**表达目标要求与允许的行为，不描述已经验证的实现。

## 权威与边界

已授权的目标是由 Codev 实现并执行真实的 Mixin 预应用和精确的配置条目清理，以日志和异常提供诊断。在调用方注册和组合的完整清理流中，所消费的目标必须包含真实引擎的处理输出，处理后的配置副本必须不再包含逻辑身份已收到引擎应用通知的条目。Codev 不额外证明应用无报错或完整完成。仅返回可移除条目名单并不能完成该清理；使用者不得被要求实现 strip 算法或 JSON 编辑，但必须按下文规定注册、配置并消费 Codev 的 Strip Transform。使用者也已明确确定，Codev 不限制输出消费方或用途；下游用途与接入由使用者决定。这是对现有归属 Spec 的更新，不是第二份 Spec。此前的范围维护没有授权规划或实施；使用者此后已另行授权文档对齐与规划准备，但未确认生产实施。

所负责的完整清理流为：**调用方提供目标和 Mixin 输入，并注册、组合 Task/Transform 组件 → Codev 在独立构建副本上执行隔离的真实预应用并收集引擎应用通知 → 调用方连接受跟踪的清理信息，组织同一操作的处理集合与消费配置/视图 → Codev 的 Strip Transform 从要求处理的副本中精确移除匹配已获通知逻辑身份的全部配置条目，包括含有配置的派生目标 → 调用方消费所有要求的已完成 Transform 结果并决定其用途**。Codev 不得限制消费方身份，不得强制仅用于编译/反编译、禁止打包或运行，或要求按用途隔离消费方路由。这不保证任意下游兼容性或安全性、防止运行时重复应用，或打包/分发行为；Codev 不代替使用者选择或实现下游路由。

原始目标和 Mixin 来源产物必须保持不变；依赖配置编辑只发生在独立副本中。逻辑上完成的结果不必是单个物理 JAR。承载配置的产物可以不同于目标 JAR；转换成功和输出用途不受限制，并不授权修改无关配置、资源或元数据。使用者可以选择将完成的副本用于编译、反编译、打包或运行；这些示例不是支持矩阵，也不是扩大清理范围的许可。

已接受的[执行流][design-flow]、[配置接口][design-types]和[生产者生命周期][design-lifecycle]，连同下文纳入的使用者后续澄清，构成选定的局部结构依据。HTML 先前的待审标签描述其发布时状态，不撤销使用者后来的接受事实。当前 PRD R3/R6 与 AC3/AC4 已接受引擎原生 required/optional 及 plugin/refmap fallback 行为。下文的后续简化取代图中先前的 Core 解耦与 service 重定向细节，不替换保留的隔离核心。ADR 对应的局部措辞仍需在同 identity 内同步；本次不修改 ADR 或 HTML。

产品动机保留在 PRD 中，已接受的架构理由保留在 ADR 中。范围更广的[差异提案][proposal]是候选背景，不是已采纳的权威。[旧 Plan][old-plan] 和 [Waves][old-waves] 描述历史交付，不是此目标的可执行安排。命名词汇仍见[核心上下文][naming]；命名空间既不是 Java 包，也不是 refmap 上下文。

## 提供的材料与解析

以下是逻辑输入/输出角色。选定名称和文件表示见下文；此表不冻结其它公开签名，也不引入新的版本化 schema：

| 角色 | 要求的行为 |
| --- | --- |
| 目标 | 可读取的目标 JAR，其类字节使用所声明的目标命名空间。输出是独立构建副本，绝不原地更新。 |
| Mixin 来源 | 承载指定配置、Mixin 类、refmap 和相关资源的产物。配置发现仅限这些来源和目标；仅出现在解析类路径上，不会注册其中的所有配置。 |
| 解析输入 | 有序依赖，包括可执行的任务插件及其资源。普通类、插件依赖、类字节和资源使用同一任务域，优先级为 **解析类路径 → Mixin 来源 → 目标**，并保留各集合内的顺序，与 ADR 保留的规则一致。 |
| 环境 | 实际生效的 side（适用时包括显式表示的未知 side）与实现依赖。通用引擎选项必须沿用 Mixin 原生读取宿主系统属性及默认行为；Codev 不得重新解释这些规则，也不得提供 Task 级公开 `engineOptions` 或等价的通用 raw override 入口。side 与命名输入保留各自的专用参数。它们决定实际操作，而不是假定的 Loader 环境。 |
| 命名输入 | 可选映射文件与显式的来源/目标命名空间，以及需要时的 refmap 上下文。名称兼容时不要求映射。 |
| 目标位置与消费方 | 为转换目标与处理后的依赖副本提供独立目标位置，且与每个受保护输入不同。输出可用性取决于所请求组件完成生产与发布，或有效复用对应当前输入的构建结果，与下游用途无关。正常完成的 Task 目标可以作为已应用目标消费，不会自动成为已 strip 的目标；完整清理流要求消费所有对应的已完成 Transform 结果。独立提供的旧 JAR 路径不是当前完成的证据。 |

除下述引擎原生处理政策涵盖的情形外，不可用的必需引擎输入、格式错误的适用引擎配置，以及有歧义的必需引擎输入解析，必须明确失败，而不是猜测执行输入。下文单独规定的 Strip 信任输入边界不要求额外证明输入合法的验证流程。配置、parent、类、plugin 和 refmap 的实际读取使用提供的输入与定义的加载优先级；不要求它们来自同一物理 JAR。side/plugin 选择、required/optional 处理及 plugin/refmap 可用性或 fallback 由引擎负责。引擎正常处理缺失的 plugin/refmap（包括仅记日志或返回默认 mapper）时，不得升级为 Codev 失败。必要 mapping 输入与显式请求的 refmap 上下文仍是要求。不同 JAR 间重复的配置资源路径或清理身份，本身不是无效输入，不得触发逐来源唯一性检查。清理匹配使用下文的逻辑身份，不使用来源标识或来源记录产物；这不替代保留的业务输入与 I/O 职责。

平台类与 Codev/Mixin/ASM 实现集合保留其定义的加载域。不得在资源来自任务输入的同时，让仅存在于宿主的应用类覆盖任务类。任务依赖不得替换执行集合的任意子集，也不得选择竞争的 Fabric/Forge Mixin 服务/全局属性实现。资源查找必须由输入涵盖：有意提供的外部文件功能需要跟踪其内容；不允许隐式回退到当前目录或宿主类路径。归档类名在所有宿主上都使用 ZIP `/` 分段，包括 Windows。

loader 资源打开边界采用 JDK `getResourceAsStream` 语义：打开资源时的 `IOException` 可以返回 `null`，按资源不可用处理，不保留原始 cause。Codev 不得仅为恢复该 cause 增加打开包装或预读。由此不可用的必需输入仍必须明确失败；原生 plugin/refmap 不可用可以遵循引擎的正常 fallback。此例外仅涵盖打开阶段：获得流后的实际 read/close 失败、直接文件/JAR I/O、输出写入与 selector 恢复仍保留其失败义务。引擎内部捕获异常并正常 fallback 仍遵循原生政策；这不授权 Codev 捕获并忽略失败，也不保证每种被引擎内部捕获的异常均外传。

## Mixin 配置发现与 handler

宿主侧 Loader 发现使用 `MixinListingRule : FileListingRules`，协变返回 `load(root: Path): MixinConfigHandler?`，以及 `MixinConfigHandler : ListedFileHandler`。复用 Core 签名，不将其扩展成 Mixin 或 Jar-in-Jar 框架。Core `list`/`remove` 表达列出引用与编辑引用声明，不专指 included JAR，也不要求删除实体文件。Mixin handler 保留 `references: List<MixinConfigReference>` 快照，携带 `resource: String` 与 `side: ConfigSide`；`list(root)` 暴露引用资源。资源/side 关联与显式 metadata 编辑仍由 Mixin 负责，不另设 `environments` 能力接口。

`MixinConfigHandler` 必须通过 `remove(root: Path)` 保留真实、显式的当前 metadata 编辑能力，不得暴露公开 `removeConfigs` 入口。移除该公开入口有源代码/二进制兼容影响；仓外调用方未知，不得宣称没有兼容影响。这是目标接口要求，不宣称代码移除已经完成。Fabric 负责其 JSON 适配器。`ForgeMixinConfigHandler` 只处理 Manifest `MixinConfigs` 的逗号分隔引用；`NeoForgeMixinConfigHandler` 只处理 `META-INF/neoforge.mods.toml` 的 `mixins` 表及其 `config` 值。发现必须遍历所有适用的 listing rules：两种格式同时存在时，不得以一方优先/fallback 隐藏另一方。不要求组合 handler 或跨格式集合相等条件。不得将 TOML 的 `environment` 等扩展字段解释成 Fabric side。

各适配器在实际装载/编辑边界解析、校验自身业务字段，并基于当前 metadata 编辑，保留无关属性、字段、表和未知内容。已装载的引用快照不得覆盖后来新增的引用；不得仅因快照过期拒绝编辑。解析与编辑留在这些边界，不另设重复预读/引用验证流程。TOML 的 load、save 和 close 由其适配器负责，真实失败必须传播。这不授权预应用期间自动编辑 metadata。`StripMixins` 既不得发现 Loader metadata，也不得调用这些编辑方法；其精确配置数组编辑独立于 handler。设计不冻结 enum 的全部取值、额外签名/ABI 或新的 null/空 handler 政策，也不重设计 Core 或 Jar-in-Jar。

## 命名与环境语义

没有映射元组时，使用实际生效的默认/显式设置进行普通引擎名称解析，而不是无条件新增 `REFMAP_REMAP=true`。提供任意映射组成部分时，都要求可读取、有效的映射文件，以及在其头部存在的非空来源和目标命名空间；验证必须先于输出写入。来源命名空间描述 **refmap 解析之后**的选择器；目标命名空间描述输入目标字节码。不得根据文件名或 Loader 名称猜测方向，也不得假定 `official` 是 `named` 的别名。

refmap 上下文是独立的实际生效输入。显式请求的上下文必须存在，并在实际 member 与 class remapping 中保持固定，包括存在冲突的宿主默认值时；否则可以使用引擎所定义的、可用且无歧义的默认上下文。存在多个上下文而没有这样的默认值时，要求显式选择。仅提供上下文不会启用映射模式。不得仅因缺少 refmap 就拒绝无 refmap/默认 mapper 输入，包括在普通选择器链足够时的映射模式。

使用 ADR 的锁定引擎 **`refmap(reference) → MemberInfo → environment remapper chain`**，配合 mapping-io 适配器，而不是临时进行 refmap JSON 字符串替换。Mapping-io `0.7.1` 是保留的仓库先例，不是支持每种映射格式或推断继承成员的承诺。局部适配器改名为 `TinyMappingRemapper`，不再名为 `ExactMappingRemapper`；这是重命名，不将输入限制为 Tiny-only。现有 `MappingReader` 格式处理及下述 owner/name/descriptor、方向性、null/未映射和歧义语义保持不变。合同不要求整个 Codev remapper 服务或新的 remapper 架构。

成员查找必须使用来源 `(owner, name, descriptor)`，并从同一映射条目获得目标名称。类、字段描述符、方法参数/返回类型与数组元素类型按来源 → 目标映射；反向/unmap 按目标 → 来源。缺失映射或 null 目标名称时，受影响的组成部分保持不变；null 成员名称仍为 null。owner/descriptor 不完整时，只有可用身份能证明唯一性才允许重命名。否则保留选择器不变，给出歧义诊断，让引擎执行普通匹配和必需失败处理。禁止取第一个同名匹配，或推断借用另一 owner 的继承映射。不得静默改写不支持的自定义 refmap 形式，也不得宣称支持它们。

例如，`a/A.run(I)V`、`a/A.run(Ljava/lang/String;)V` 和 `a/B.run(I)V` 仍是不同的查找；没有 owner 和 descriptor 的 `run` 不能借用第一个的映射。`([La/A;)La/B;` 按声明方向映射每个类组成部分。语法有效但语义错误的命名空间声明，不能由 Codev 推断为正确；必需的解析失败仍是可见的引擎失败。

## 操作所有权与资源

每次操作必须创建**全新的操作运行时类加载器**，并拥有自己的 bootstrap、Codev 服务/全局属性状态、环境、transformer、配置注册、元数据缓存、remapper、结果/诊断状态、扩展实例与任务插件静态状态。应用 Gradle 插件不得初始化共享转换环境。成功、失败或取消的操作不得通过保留的 Codev 所有状态改变后续操作。

宿主 `Mixin` Task 必须负责 Gradle 参数、输入/输出与缓存跟踪，以及 Fabric/Forge/NeoForge 配置引用发现。每次调用必须创建一个 `IsolatingMixinClassLoader`，用它加载处理整个目标 JAR 的真实 Kotlin child 函数。child 必须解析配置与 mapping、初始化引擎、将归档处理到暂存目标并收集通知。关闭其归档后，它必须返回已完整物化的 JDK Map/Set 值，携带配置资源路径与原始条目字符串。宿主必须先关闭 loader，再写完条目文件并完成两个具名输出。Kotlin/serialization DOM 对象和活的引擎对象都不得跨越该边界。不指定完整的固定函数签名。

实现采用 Kotlin-first 与已有 Kotlin serialization DOM，而非把旧 Java 类图翻译成同构框架。资源访问与关闭使用普通 Kotlin/NIO、现有 JAR 与 loader 资源 API，配合限定作用域的 `use`；序列化留在宿主输出写入及 Strip 输入/编辑职责内。不需要独立的 `ArchiveResources` 层、`AppliedMixins` codec 工具或同形替代层。不要求 `EngineOperation` 控制层、`StrictJson` 包装或替代语法扫描器、自建引擎 JAR SHA 白名单或通用 `OperationPublication` 框架。去除这些框架前提不得去除真实隔离、Codev SPI/服务所有权、一致的类/资源解析、原始异常 cause（上文 JDK 资源打开边界除外）、TCCL 恢复、资源关闭或真实执行依赖跟踪，包括影响输出的 Kotlin/serialization 依赖。

Codev 执行实现、`net.fabricmc:sponge-mixin:0.15.0+mixin.0.8.7` 及其选定的 ASM 依赖构成一个一致的实现集合。跨类加载器的值必须使用 JDK 类型/简单值；不得在不同域间强制转换不兼容的 Mixin/ASM 实例。影响输出的继承原生选项及其相关未设置/default 状态，仍须作为可识别、可跟踪的构建输入。内部宿主属性观测服务于 Gradle 输入跟踪，不是隐藏的逐 Task 覆写 API；Codev 不得重算 Mixin 选项继承/解析、注入独立选项快照或适配选项 getter 字节码。不要求操作独立的 `System` 属性表，也不承诺共享 JVM 中每个 Task 有独立 raw 值。

服务选择在短初始化窗口内使用原生 `mixin.service`（`IMixinService`）与 `mixin.bootstrapService`（`IMixinServiceBootstrap`）selector，替代 loader 合成的 service 资源重定向。在任何 child 引擎初始化之前，参与约定的 Codev 操作/宿主副本必须共享一个 JVM 级初始化互斥边界，保存两个 selector 的原值或未设置状态，临时选择 Codev 的 child 域 service/bootstrap，初始化并缓存 child service，同时安装/缓存该操作独有的 child global-property service。`IGlobalPropertyService` 没有原生 selector property；仅设置两个 selector 并不足够。global-property 安装仍是锁定引擎的适配接点，不是新的公开 selector，也不规定私有字段合同。

必须在 `finally` 中恢复两个 selector，包括初始化失败或取消时；原先未设置的必须恢复为未设置。恢复失败必须向外传播并保留任何先前 cause，不得报告成功。恢复后才释放初始化互斥；不得串行化整个转换。缓存的 child service/global-property 状态仍由操作独有，因此转换可以独立并发继续。不参与约定的其它宿主可能观察或干扰这些临时 JVM 全局值；该窗口不提供不可观察的沙箱。不选定属性租约或通用锁框架。修改过的 TCCL 也必须在 `finally` 中恢复；所持类加载器、流和 ZIP 文件系统必须在成功、失败或取消后关闭。

Codev 不得显式轮询 `Thread.currentThread().isInterrupted`。仅设置线程 interrupt flag 时，如果调用的 API 未抛异常，不保证主动检测到该标记或阻止完成/发布。I/O、引擎、close、move 或取消 API 实际报告的取消或失败仍必须向外传播，并履行要求的恢复、关闭与失败清理；不得将真实取消当作成功。

独立并发操作必须拥有独立可变状态与临时位置，并在语义上与串行处理一致。允许在一次操作内顺序处理目标；不暗示并行加速保证。冲突的输出位置必须被拒绝，或在完成前由一方独占，绝不能交错混合结果。这包括 Task 的两个输出在物理上彼此独立。共享输出冲突指生产方写入同一物理目标位置，不指多个消费方读取完成输出。不要求覆盖独立构建任意目录的通用锁框架。

任务插件可以在限定环境内初始化扩展。类加载器隔离**不是任意代码沙箱**，不能据此涵盖插件写入的全局属性、外部线程、原生状态、文件系统或网络副作用。没有证据时不得宣称这些影响受到隔离。当前目标不要求自动升级引擎、捆绑/bootstrap MixinExtras，或推断 Loader 版本谓词。实际不兼容的字节码/配置、缺失注入器和 bootstrap 失败保留引擎失败语义；不认证更广泛的 Minecraft × Loader × 扩展支持矩阵。

## 真实结果与诚实诊断

Codev 必须在提供的目标上调用真实 Mixin 引擎，并收集引擎提供的应用通知。child 只进行通知键所需的原始条目读取（需要时包括 parent 遍历）、side/mapping 设置、配置注册与真实逐 entry 转换；必须保留目标 JAR 中的 `@Mixin` 定义。不得为预验证重复读取 DOM，不得对每个声明的类/plugin/refmap 预扫存在性或同 JAR 来源（包括不适用于当前 side 或被 plugin 排除的条目），不得独立证明 parent 有效性，也不得在转换后巡检全部配置来复验 active/environment/plugin/refmap 一致性。条目读取遍历中的普通 visited 终止记录不是第二套 parent 验证器。不得将这些检查换名搬到其它 helper。实际读取、下述默认 UTF-8 解码策略、业务形状和路径、必需 mapping/context 选择、实际 API 报告的取消以及真实引擎/I/O/close 异常仍由相应职责承担。收到引擎应用通知，对应的清理逻辑身份立即取得资格；仅配置发现或 prepared/candidate 名单不能使其取得资格。通知不认证跨目标或物理来源的完整应用、处理无报错或最终字节码效果。Codev 不得自行验证注入语义、重建或比对原生目标义务或选项规则、比对字节码效果，或解析日志作为清理资格门槛。引擎正常返回既不需要作为身份资格的额外证明，也不证明所有请求的应用都成功；Codev 自身的输出生产义务仍然适用。

通知记录必须使用已接受的 `GradleMixinRecorderExtension` 接点，它能够取得 config 及其对应的 Mixin，再将二者映射回完整配置资源路径与原始显式条目字符串。不得仅依靠 audit 类名猜测配置归属，也不得引入新的通知归属证明门槛。该接点不认证每个候选、全目标完成或最终效果；仅发现仍然不够。

正常的应用/构建日志必须让引擎的处理和诊断可供使用者自行阅读。Codev 不得解读这些日志来判定应用成功。Codev 自身的失败必须通过日志或向外异常可见，标识阶段、已知时的相关配置或目标，以及可获得的底层原因；反射包装必须保留可获得的 cause。上文 JDK 资源打开边界不保证提供资源不可用的 cause。未知归因或影响必须明确保持为不确定，绝不能编造身份或宣称完整应用。诊断使用日志和异常，不是必需的返回载荷，也不落盘诊断账本。这里没有选定日志载体、字段、格式、返回日志回调、独立 records 文件、manifest、receipt、哈希协议或消费方复演。

引擎抛出的异常必须向外传播并停止受影响的生产；Codev 不得吞掉异常或修改注入器要求以制造成功。引擎只记报错日志或仅部分应用 Mixin，但正常返回时，这本身**不得使 Codev 的输出生产失败，也不得取消已收到通知的清理身份的资格**。这包括原生 side/plugin 决策、required/optional 行为与 plugin/refmap 不可用时的 fallback，包括正常返回默认 mapper；Codev 不得通过预扫或事后检查重新裁定这些结果。必需 mapping 与显式 refmap 上下文语义继续适用；不得仅因出现未知自定义 `refmapWrapper` 字段就拒绝，也不得静默改写或宣称兼容它。此类处理可能留下修改；部分应用不是回滚的证明，完成输出不得被标为“所有请求的 Mixin 均成功”。旧的选择性残留修改/运行时保留拒绝规则，不是此目标的致命规则。Codev 自身输出生产失败或完成未知仍是失败，区别于应用完整性或效果未知。

没有适用配置的有效操作，可以完成一份未改变的构建副本。没有应用通知时，移除集合为空，不移除任何配置条目；这不声称引擎没有进行处理。Codev 不得编造已获通知的身份或复用此前操作的影响。空移除集合既不确立输出完成，也不确立应用成功，引擎原生政策之外的无效输入也不能走空结果成功的捷径。

## 已应用输出与精确依赖清理

对于调用方注册、组合并消费的完整清理流，Codev 必须产出完成的转换目标和处理后的依赖副本，其配置不再包含任何匹配已取得清理资格身份的物理出现位置，包括清理含有配置的派生目标。调用方必须消费所有要求的 Transform 结果；仅有正常完成的 Task 目标是已应用目标，不是清理完成的证明。这些是实际结果要求，不是要求聚合 provider 或统一的 Codev 交付出口。逻辑身份精确为**配置资源路径 + 原始 Mixin 数组条目字符串**这一对值。资源路径是配置的归档资源路径，不是来源 JAR 的文件系统路径。条目字符串是配置的 `mixins`、`client` 或 `server` 数组中所写的 JSON 字符串值，取包名展开或名称映射之前的值；不得用展开或映射后的类名替代它。数组分区、索引和物理来源不是身份组成部分。

逻辑身份一旦收到引擎应用通知，即取得进入移除集合的资格，无需另行证明处理无报错、跨目标或物理来源完整应用，或最终修改效果。其它位置的部分、失败、跳过或未知处理，不得取消该已获通知身份的资格，也不得因此保留其任何匹配位置。逻辑身份未收到应用通知的条目必须保留。通知收集必须保留精确的配置资源路径与原始条目字符串；不得凭发现、类名相同或未知归因编造键。引擎异常及 Codev 输出生产失败仍停止受影响的生产；它们不是额外的应用资格检查。

对于每个具备资格的身份，Codev 必须从所有处理后的依赖副本的 Mixin 数组中移除具有该精确资源路径和原始条目字符串的每个物理出现位置。匹配必须对两个值都使用精确相等，不使用来源标识、来源路径、哈希或逐来源唯一性检查。一个数组内的重复出现、跨 `mixins`、`client` 和 `server` 的匹配，以及不同 JAR 中的匹配，必须一并移除。另一物理来源中的同键出现位置也必须移除，即使没有单独确认它已应用；这是要求的批量后果，不得以来源歧义拒绝。不同资源路径或原始条目字符串不得匹配。身份不具备资格的条目必须保留。

`StripMixins` 必须执行该清理；仅提供名单不得使使用者需要自行实现清理算法或 JSON 编辑。使用者或集成插件必须按下文规定注册、配置并消费它。对于 Mixin 产生清单的完整流，通知资格决定生产方集合；独立而言，Strip 的移除依据是提供给 `StripMixins.Parameters.removalsFile` 的有效文件，不是引擎通知证明。实际解析/DOM 访问失败或无法执行要求的精确编辑时，必须通过向外异常使清理失败，绝不能静默宣称完成；Strip 不得另加输入合法性预扫描。有效空移除集合或没有匹配条目时，必须保持配置内容不变。

清理必须保留其余配置字段及值（包括未知 DOM 内容）、保留条目的顺序、其他条目和无关归档资源。需要精确编辑时，JSON 格式不必逐字节一致，但精确移除以外的已解析 DOM 内容必须保持语义不变，仅受下文重复对象键策略约束。该清理不得删除或改写 Mixin/helper 类、refmap、整个配置文件（包括显式数组变为空的文件）、Loader 元数据及引用。在 Mixin 产生清单的流中，插件/父级或动态贡献不是编造原始显式条目字符串或引擎通知的许可；生产方仍要求精确逻辑身份已获通知。

具名文件输出和内部清理通信都不要求失败原因、诊断或未知条目名单、状态布尔值、目标 obligation 数组、来源/类路径清单、哈希、重复绑定/schema 或 records 路径。运行时集合与条目文件支持精确批量匹配，而非完整条目认证，不得为清理增加来源身份或唯一性条件。跨类加载器值必须满足 Accepted 的 JDK/简单值边界，在生产方类加载器关闭后仍可使用，不带活的引擎对象。

### 条目文件与 JSON 语义

`Mixin.outputFile` 必须是已应用目标 JAR 文件输出；`Mixin.appliedMixins` 必须是第二个受跟踪的文件输出，编码已获通知的移除集合。其 JSON 对象将每个**完整配置资源路径**映射到**原始 Mixin 数组条目字符串**的数组，读取后按字符串集合处理。例如，`{"configs/example.mixins.json":["Common","Client"]}` 携带该资源的两个精确键，不是经包名展开的类名。不要求来源、证明、状态或版本字段。child 返回对应的已物化 JDK Map/Set；宿主在 loader 关闭后写出此文件。

空对象是有效空移除集合；空数组不为其资源贡献任何条目。数组中重复字符串归一为同一集合成员，不改变全部出现位置的移除语义。支持的条目文件形状是归档相对配置资源路径到字符串数组的对象；适用配置的 `mixins`、`client`、`server` 字段存在时为字符串数组。这些形状描述所提供的数据，不要求 Strip 手写复验每个根、值或元素类型。Strip 信任所提供的输入，只按配置路径和原始字符串精确相等过滤这三个数组；不得裁剪、归一化、展开或以其它方式改写匹配键。不得额外增加名称/空白/控制字符检查、字符/路径/业务合法性预扫描、自建 ZIP 重名集合或输入 size/CRC 复验。写出 STORED 输出条目所需的 size/CRC 仍属输出写入职责。实际解析、DOM 访问、ZIP/I/O、写出和关闭失败必须传播，文件缺失或不可读不得变成空集合。Strip 既不保证拒绝每一种坏输入，也不保证坏输入处理成功。下述默认 UTF-8 解码策略与输入/输出保护继续适用。

Codev 的 JSON 读取/编辑必须使用已有 Kotlin serialization DOM，包括适用的 metadata、配置/parent、refmap 与条目文件路径。**同一 JSON 对象内的重复键遵循所用 Kotlin serialization 库版本的标准解析语义；Codev 不额外保证拒绝它们。** 这也适用于重复配置字段和未知嵌套对象键；不规定固定的最后值策略，也不保证超出库 DOM 表示的重复文本成员保留。

**JSON 字符串内未转义的 U+0000–U+001F 控制字符同样遵循所用 Kotlin serialization 库版本的标准解析行为；Codev 不额外保证拒绝它们。** 两项语法策略适用于上述全部 Codev JSON 路径，包括未知字段中的字符串；Codev 不得对这些字符串增加控制字符扫描。它们不豁免适用的 metadata/引擎输入业务规则，也不改变支持的条目文件/配置形状；Strip 遵循上文信任输入边界，不额外手写类型、值或路径验证。本 Spec 中对格式错误或无效 JSON 输入的表述均受这两项语法策略及该 Strip 边界约束。UTF-8 读取必须采用已安装库或引擎的默认解码行为，包括在相应解码器如此处理时替换非法字节序列；Codev 不得增加严格解码或字节验证扫描。这适用于 metadata、配置/parent、refmap 及条目文件 JSON，包括未知字段。既不保证拒绝每种非法字节序列，也不保证其处理成功，或不同读取器具有固定相同的替换结果。原生 ReferenceMapper 的解码/解析和正常返回的 fallback 仍由引擎负责；不要求每一种坏输入都转成默认 mapper。这些语法及解码策略之外的其它格式错误 metadata/引擎输入，仍遵循实际解析器和原生失败/fallback 政策；Strip 实际解析/DOM 访问失败必须传播，不另设证明输入合法的验证流程。必要的 metadata/引擎业务形状、字段类型/值、字符串元素、归档路径验证与输入保护继续适用。不得保留 `StrictJson` 或构建等价的语法/重复键/控制字符扫描器。这些策略不规定固定的边缘情况结果，也不意味着与此前解析器等价。

`StripMixins.Parameters.removalsFile` 与来源无关：可以连接 `Mixin.appliedMixins`、其它任务输出或手写合规文件。Strip 必须只按所提供集合精确编辑 JAR；不得加载引擎、发现 Loader metadata、要求生产方内存，或要求来源身份、SHA、通知确已发生的证明。文件提供者负责集合的业务选择。Strip 仍必须在上文信任输入边界内安全地产出精确编辑，但不能承诺判断手写集合在业务含义上是否陈旧。生产方依赖与 Gradle 当前输入复用仍不得让失败或陈旧生产冒充当前成功。该独立能力不扩大下文同操作完整流的处理集合。

## 预应用 Task 与逐 JAR Strip Artifact Transform

选定结构是 **`Mixin` 预应用 Task 生产方加逐 JAR `StripMixins` Artifact Transform**，不是在组合任务、两个任务或 Transform 之间尚未解决的选择。保留这些名称，但不意味着保留旧版全部删除语义或完整旧 API/ABI 兼容。Codev 实现两个组件，执行真实预应用和精确 strip；使用者或集成插件注册、配置并组合它们。通过 `registerTransform` 注册 Transform 类型、参数及 from/to 属性规则，是项目级配置；使用者或集成插件也选择消费配置或 `artifactView`、请求属性并消费结果。Codev 不负责自动接线、配置选择或统一的目标/依赖交付出口。不得要求使用者实现 strip 算法。

每次操作的生产方必须读取提供的**原始目标、原始 Mixin 来源与原始解析输入**，绝不能读取自己的 strip 视图。完整清理流中，使用者或集成插件必须将处理集合组织为恰好该操作的原始 Mixin 来源 JAR 加其派生转换目标。该集合的每个 JAR 必须使用该操作具备资格的移除集合，经过同一个逐 JAR Strip Transform；含有配置的派生目标也必须先 strip，才能称为已清理。没有匹配配置或移除集合有效但为空时，transform 必须保留配置内容和无关资源。原始目标仍是受保护的生产方输入，不能在清理集合中代替其派生目标。

对于该 Mixin 产生清单的完整清理流，使用者或集成插件的集合接线必须遵循该操作提供的原始集合和派生目标关系。不得把清理扩大到整个运行时解析类路径或任意外部配置，不得将已 strip 来源作为生产方输入消费，也不得合并不同操作的移除集合。仅用于解析的产物不是清理成员，除非它也是提供的 Mixin 来源。集合接线不得序列化来源身份、冻结来源目录或将来源复制到新清单中。重复配置路径/条目字符串保留上文精确的全匹配语义；必要的引擎输入解析验证与 strip 身份分开。

Task 必须将 `Mixin.outputFile` 和 `Mixin.appliedMixins` 作为两个受跟踪的文件输出提供，用于下游执行和正常缓存恢复。对于完整流，使用者或集成插件必须将 `appliedMixins` 输出 provider 绑定到 `StripMixins.Parameters.removalsFile`，并保留所请求消费需要的生产方引用和构建依赖。条目文件必须携带已获通知的配置资源路径/原始条目字符串集合，并且无需生产方内存或活的操作类加载器即可使用。它是构建数据，不是独立应用 records 或审计证明。成功产出的有效空集合不同于缺失、无效或陈旧的生产方信息：后者不得被解释为空，不得从目标文件猜测，也不得用于绕过要求的清理。选定属性名与编码不冻结物理文件名、文件内排序、provider 接线细节、保存/恢复机制或缓存算法。

调用方可以将 Task 正常完成的目标输出作为已应用目标消费；该输出不会自动成为已 strip 目标，也不是清理流完成的证明。请求已清理输出的调用方必须带着要求的生产方依赖，消费对应 Transform 结果，包括含有配置时已 strip 的派生目标。要求的 strip 失败、缺失或未确认时，必须将失败传播到该消费，不得仅因另一个组件产出 JAR 就报告整个请求流完成。这不要求一对在所有成员间共同设门的 Codev 交付出口、跨任意用户任务的事务，或某种下游用途选择。

## 构建副本、完成与消费

两个生产者拥有独立文件生命周期，不是共享事务、同步阶段或共同发布框架：

- `Mixin`：验证输入与两个输出路径 → 创建隔离 loader → 处理到暂存目标并收集通知 → 关闭归档、返回已物化 JDK 集合并关闭 loader → 写完 `appliedMixins` → 完成 `outputFile` 与 `appliedMixins`。在该顺序成功完成之前，两个文件均不是完成的 Task 输出。
- `StripMixins`：读取 `removalsFile` → 不修改原始 JAR 地读取它并精确编辑匹配配置 → 写入 Gradle Transform 工作区 → 所持资源关闭成功后才交付。它不调用 Mixin 引擎或 metadata handler。

各组件要求的验证和输出身份保护必须先于破坏性输出操作；Strip 的信任输入边界不移除输出保护，也不要求独立的输入预扫描。目标位置不得覆盖任何实际输入或与其构成别名，包括真实路径别名、硬链接或受保护目录包含关系。归档处理不得向所拥有的输出区域之外写入；实际路径访问或写入失败必须传播。输入产物必须在每种退出路径上保持不动；构建副本必须保留未转换的目标条目/资源，依赖资源也必须保留，上文精确的配置条目移除除外。

引擎调用返回、Task/Transform 完成，以及可供调用方所请求消费使用，是不同边界。引擎转换正常返回，不证明目标写入、依赖清理或组件发布成功。身份收到通知即取得资格，但 Task 内部清理信息只有在自身输出生产成功后，才能作为完成的下游输入使用，包括输出写入、所持资源关闭、运行时退出和 Task 自身发布。这些物理生产要求不认证 Mixin 完整应用或无报错，也不得成为额外的资格检查。内部通信和暂存数据不得被宣称为完成的组件输出，也不得让调用方绕过其所请求消费所需的处理。

每个 Task 或 Transform 必须将写入保持在暂存状态，不可作为已完成输出使用，直到其自身生产或精确编辑、输出写入、所持资源关闭/退出与发布全部成功。完成的组件输出可以向下游阶段、有效构建复用或调用方消费提供该组件实际完成的成果；它们不确立其他组件完成。任一这些阶段失败或完成未知时，必须阻止受影响输出作为完成结果被消费。清理失败必须传达到调用方，不得把已产出的 Task 目标当作整个请求清理流成功。这是组件生产方/消费方要求，不是独立 records 协议、跨任意任务的事务或指定的多文件原子重命名。

调用方的消费接线必须保留要求的成功生产/清理依赖，或获得针对当前输入正常恢复的已完成组件结果。对于请求转换目标和对应处理后依赖副本的流，调用方必须组合并消费这些输出；已清理依赖不得代替目标，无关旧输出路径不得代替当前完成。这些组件生产和请求流义务不受使用者预期用途影响。它们不强制按用途隔离路由，也不要求 Codev 选择下游接入。Task/Transform 结构、同操作处理范围，以及调用方负责注册、参数绑定与消费的职责已经固定。具名文件属性及其职责已经固定；其它 task/provider API 细节与调用方接线机制仍是实现选择。不要求统一的操作结果对象或聚合交付 provider。

## 输入变化、缓存恢复与失败消费

Gradle 输入/输出跟踪必须覆盖每个影响输出的输入：目标与 Mixin 来源内容、完整有序的运行时解析类路径（包括插件方法体/资源）、实际生效的 side/选项/设置、执行实现依赖、映射内容/方向性命名空间，以及所选 refmap 上下文。这包括实际影响输出的继承宿主系统属性及其相关的未设置/default 状态；内部观测必须与 Mixin 实际的原生读取一致。Codev 固定选择 `mixin.service` 与 `mixin.bootstrapService`，因此它们的原宿主值不是实际生效的原生选项输入；输入跟踪不得捕获另一操作的临时 selector 值。其实现由 implementation classpath 跟踪涵盖。其余影响输出的原生选项及未设置/default 状态继续跟踪。取消公开 raw override API 不会移除这些受跟踪输入，也不会把整个无关 JVM 环境变成输入。内部属性载体、枚举、序列化与缓存算法仍是实现选择。对于可执行插件，仅 `@CompileClasspath` 不够。仅修改插件方法体、资源、配置、映射、实际生效环境或输出相关宿主系统属性时，必须产出对应当前输入的结果，而不是复用陈旧行为。

输入/输出跟踪和正常复用必须覆盖 Task 产出的目标与清理信息文件、每个逐 JAR Transform 的参数和输入产物，以及处理后的输出。每个 Transform 必须将所提供 `removalsFile` 的内容作为影响输出的输入跟踪，并保留必要的生产方依赖。在 Mixin 产生清单的完整流中，该文件必须是当前操作的已获通知集合，而不是全局或跨操作并集；调用方提供的注册与消费接线必须保留该跟踪。正常的 `UP-TO-DATE` 或 `FROM-CACHE` 结果必须对应当前受跟踪输入，并在没有生产操作内存状态或已关闭执行环境的情况下仍可使用。这两个状态都不会执行本次调用的引擎，也不会提供新的内存返回值；不得将其视为新的应用证据。清理阶段必须获得有效的当前输入内部信息，或复用整个要求集合（包括派生目标）的正确处理输出；缺少内存返回值不是跳过清理或猜测移除项的许可。

仅文件存在不得确立完成。构建依赖和输出跟踪必须阻止中断发布或当前生产方失败冒充有效复用；旧文件不得替代失败的当前结果。缺失、无效或陈旧的内部清理信息必须阻止完成结果的消费，而不是冒充有效空集合，除非正常构建执行/恢复提供有效的当前结果。消费方不必复演引擎处理或验证审计产物。除选定的文件编码和生产者生命周期外，存储/恢复、组件发布与诊断细节仍是实现选择；调用方提供的接线必须保留要求的依赖，仅内存通信不够。不要求独立 records、额外 manifest/sidecar 或独立证明/持久化协议。当前生产方/陈旧结果要求针对生产依赖与复用，不是对独立提供的手写移除集合进行来源或年龄检查。

引擎抛出的异常必须向外传播。导致 Codev 无法完成自身输出生产的实际输入读取/解析/DOM 访问、转换、依赖清理、输出写入或资源关闭/运行时退出失败、被调用 API 报告的取消或已触发的配置超时，必须向外抛出异常，停止受影响的生产，阻止消费方收到当前半成品或陈旧成功结果。仅 interrupt flag 不要求主动检测，也不要求据此拒绝发布；上文不轮询的边界不豁免任何实际报告的失败。仅引擎记报错日志、部分应用或原生 plugin/refmap fallback 但正常返回，不得被转为 Codev 失败；此处无效输入失败受该原生政策约束，不豁免必需 mapping/context 或 Codev 业务/I/O 义务。此前输出可以在物理上仍存在，但当前失败调用不得将其宣称或路由为当前成功，也不得静默回退到未转换目标以假装所请求流成功。不完整的自有发布必须被移除或失效。不得删除原始输入和无关输入。不承诺自定义默认超时或恢复旧输出。

重试必须使用全新的操作状态，输入相同时，在语义上与干净调用一致。输出所有权必须允许安全的失败清理，不删除另一操作的结果。如果不能确立 Codev 组件生产/发布、依赖清理完成或与当前输入对应，受影响输出就不可消费；不得编造精确身份以绕过该失败。Mixin 应用完整性未知不是此类生产失败，不得因此将已获通知的身份移出移除集合。这些是消费方可见的要求，不是对摘要、验证 receipt 或新注册框架的要求。

| **Reuse and input changes** / R3, R5, R10, AC3, AC5, AC11 | 通过调用方提供的注册/消费，检验正常 `UP-TO-DATE` 和构建缓存恢复，包括没有生产方内存的新消费方。恢复受跟踪的 `Mixin.outputFile` 与 `Mixin.appliedMixins`，再执行或正确复用每个要求的 strip，包括派生目标。独立 Strip 使用时也跟踪所提供的 `removalsFile`；不意味着检查通知来源或手写文件年龄。Transform 参数、输入产物和输出必须保持受跟踪；消费的组件结果保持当前且可用，不需要新的引擎返回。分别检查有效空集合与缺失、无效或陈旧信息：后者不能以空集合或仅因目标文件存在而授权完成。修改配置/插件/资源/映射/环境输入，包括仅修改一个输出相关宿主系统属性或其未设置/default 状态，得到对应当前结果，不得错误复用陈旧结果。原宿主 service/bootstrap selector 值不是选项输入；检查不捕获临时 selector 值，并继续跟踪 implementation classpath 变化及其它所有影响输出的原生选项。缺失内存和缓存状态都不能跳过清理、编造可移除条目或算作新引擎运行。 |
| **Failure safety** / R6, R10, AC4, AC5, AC11 | 有效输出之后，检验实际输入读取/解析/DOM 访问失败、引擎抛出的异常、被调用 API 报告的取消、清理失败、输出写入/中断发布失败，以及所持资源关闭/运行时退出失败。确认 Codev 不显式轮询 `Thread.currentThread().isInterrupted`；仅有 interrupt flag 而没有 API 抛出失败时，不必阻止完成/发布。另行检验 I/O、引擎、close、move 及取消 API 真正抛出的异常：均不得变成成功，要求的恢复/关闭/清理仍适用。仅引擎正常返回或资源关闭不得允许消费 Codev 的半成品或陈旧输出；生产失败以向外异常提供阶段/原因及已知身份或明确不确定性。仅引擎记报错日志或原生 plugin/refmap fallback 但正常返回，本身不是生产失败。单独检验 loader 打开 `IOException` 按 JDK 返回 `null`/资源不可用，不断言原始 cause：必需输入不可用仍须明确失败，原生 plugin/refmap fallback 可以正常返回。将其与获得流后的 read/close 故障及直接文件/JAR I/O 分开。真实 read/write/close 与 selector 恢复失败仍须传播，受上文原生内部捕获并 fallback 的边界约束；删除额外验证不得吞掉它们。拒绝输入/输出别名（包括真实路径、硬链接和受保护包含关系）、两个 Task 输出间的别名及冲突生产方目标位置，不修改原始产物或无关输入。归档处理不得向所拥有的输出区域之外写入；这不要求 Strip 对所提供的配置/移除键预扫路径合法性。分别检验 Task 至归档/loader 关闭、条目文件完成的顺序，以及 Strip 工作区写入/关闭：任一生产方失败都不得暴露其半成品或陈旧成功；不意味着多文件事务或跨构建锁框架。重试与干净调用一致。 |

仅 Mock transformer、字符串断言、任务实例化或依赖存在，不能确立真实引擎处理或消费构建行为。小型真实引擎与交付场景检查 Codev 使用引擎、通知到条目清理、未获通知身份保留，以及完成输出可用性；不要求独立注入语义验证器或全目标完成证明。映射检查关注 Codev 的命名输入与 remapper 行为，不是新增引擎验证器。这些条件不认证下游兼容性或路由，也不要求运行时重复应用、选择性元数据重新开放或旧 ABI 调用方。

## 已接受接口与实现边界

选定局部技术结构**已接受，不代表已实现或已验证**：

- 保留 `Mixin`、`StripMixins`、两个文件输出 `outputFile`/`appliedMixins`、来源无关的 `Parameters.removalsFile`、资源路径 → 原始字符串集合的文件表示与已物化 JDK Map/Set 返回。完整 Mixin 流与独立 Strip 输入按上文分别承担职责。不选定完整旧 ABI、child 函数的完整固定签名、新版本化 schema、文件内排序或额外 DTO。
- 宿主负责 Gradle 跟踪和 Loader 发现；全新的 `IsolatingMixinClassLoader` 运行 Kotlin 整 JAR child 函数，两个生产者各遵循选定生命周期。不依赖旧控制、解析器、SHA 或发布框架，仍必须保留真实加载/资源/SPI/输入/失败保护。
- 已选定复用 Core 签名的 Mixin 专用 listing/handler 子接口、资源/side 引用快照、分离的 Fabric/Forge/NeoForge metadata 适配器，以及基于当前 metadata 的显式 `remove` 编辑，不保留公开 `removeConfigs` 入口。Strip 不得调用这些 metadata 编辑。enum 全部取值、额外签名和新的 null/空 handler 政策仍未冻结。
- `GradleMixinRecorderExtension` 提供 config 与对应 Mixin 身份。仍须实现精确映射回原始条目，但归属不再是未决架构选择或新的证明门槛。生产方中通知即身份资格，不认证完整应用。不要求 target obligations、records、日志裁定或为证明全目标完成而适配引擎字节码。
- 已选定已有 Kotlin serialization DOM，以及所用库版本对重复对象键和字符串内未转义控制字符的标准策略。上文默认 UTF-8 解码及 JDK 资源打开失败语义也已接受。这些策略不规定固定的边缘情况结果，也不放宽 metadata/引擎业务规则或输入保护。Strip 已接受的信任输入边界移除额外手写验证，不改变精确的数组集合/全匹配语义。
- 其它 task/provider API 细节、调用方接线、私有物理文件名、完成/存储/恢复细节和缓存算法，仍是在固定文件接口与生命周期内的实现选择。不要求注册辅助工具、聚合 provider、两个统一交付出口或独立证明平台。调用方仍显式负责注册、参数绑定、同操作集合范围、属性请求与消费；下游用途/路由属于使用者。

文档接受不是新设计执行或验收的证据。使用者已另行授权文档对齐及 Work/Context/Plan/Waves 准备；本次更新不执行这些准备，也不创建/确认就绪 Plan。生产实施、代码移除和消费方重新接线仍需另行确认。已接受的隔离核心继续保留，旧 G1 仍是历史 accepted/closed 交付，而非新设计证据。已有范围内的实现与 partial 结果保留其已记录含义：本文既不将其重置为未开始，也不升级为 completed，不释放 Wave gate，不证明这些简化已经实施。同 identity ADR 的后续衔接涉及 Core 复用、分离的 metadata 所有权、原生失败边界与 selector 窗口/global-property 限制。现有重设计 Plan/Waves 需在自身范围内核对受影响的接口、资源/codec 落点、remapper 引用、selector 跟踪和定点检查；本次 Spec 更新不编辑或批准该图。

精确的依赖配置条目清理与保留 `StripMixins` 名称是要求；旧 API/DSL/ABI/processor 注册兼容或旧版全部删除语义、运行时贡献抑制、整个配置删除和 Loader 元数据改写不是要求。独立 records/schema/摘要/原生 obligation 数组、旧格式迁移、绑定证明、消费方复演或替代验证 manifest/receipt 框架也不是要求。这不授权删除其现有实现。无关 cache/lock/remapper/includes/launch/IDEA 重设计、旧 Core 测试恢复和支持矩阵扩展仍不在范围内。触及路径上的现有 AW/class-tweaker、Fabric AW、Forge AT/patch 和嵌套 JAR 行为不得退化；这不是对这些能力的重设计或新认证。
